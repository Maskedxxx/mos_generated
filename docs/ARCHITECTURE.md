# Архитектура сервиса генерации

## 1. Узлы

| Узел | Где | Принимает | Отдаёт | При ошибке |
|---|---|---|---|---|
| Реестр | `registry.py::GENERATORS`, `get_generator` | `doc_type` | экземпляр генератора или `None` | неизвестный тип → `None` → API 404 |
| Схема | `engine.get_schema` | `doc_type` | `{doc_type, title, fields}` из `SCHEMA` | — |
| Наследование | `engine.generate` | `session_id`, значения формы | значения + поля `inherited` из сессии | — |
| Генератор | `generators/<тип>.py::generate` | значения | `DocxTemplate` с подставленным контекстом | пустые обязательные → `ValueError` (API 400) |
| Сохранение | `engine.generate` | `DocxTemplate` | bytes `.docx` | — |
| Стор по организации | `engine._store_org_values`, `org_suggest`, `org_list` | значения формы | JSON-файл: нормализованное ООО → поле → до 10 последних значений | битый файл → пустой стор, без падения |
| Журнал | `engine._write_trace` | тип, сессия, значения, файл или ошибка | `logs_generated/<тип>/session_<время>[_N]/meta.json, values.json, .docx` | любая ошибка записи — в stdout, выдача документа не прерывается |
| HTTP | `api.py` | запросы | JSON / `.docx` с `Content-Disposition` | 400 / 404 |

## 2. Контракт API

| Метод и путь | Ответ |
|---|---|
| `GET /api/graph` | `{start, nodes: [{doc_type, title, code, position}], edges}` |
| `GET /api/types/{тип}/schema` | `{doc_type, title, fields: [{key, label, type, required, source, hint?, default?}]}` |
| `POST /api/types/{тип}/generate` `{session_id, values}` | `.docx` |
| `GET /api/types/{тип}/download?<ключ=значение…>&session_id=` | `.docx` (нативное скачивание браузером) |
| `GET /api/orgs` | список известных наименований организаций |
| `GET /api/org/suggest?org=` | `{ключ_поля: [значения…]}` для автозаполнения |
| `GET /api/session/{id}/values` | накопленные значения сессии |
| `GET /` | `static/index.html` |

## 3. Ключевые решения (ADR, кратко)

**ADR-1. Шаблоны Word + docxtpl, а не генерация текста моделью.** Документы заказчика —
утверждённые формы с постоянным методическим текстом; меняются только реквизиты.
Подстановка в шаблон даёт побайтово предсказуемый результат и сохраняет форматирование
оригинала. Цена: любое изменение формы у заказчика — правка шаблона руками.

**ADR-2. Единая точка `engine.generate()`.** Оба HTTP-пути (JSON и GET-скачивание) идут через
неё, поэтому наследование, стор по организации и журнал реализованы один раз и не расходятся.

**ADR-3. Стор значений по организации — файл JSON с нормализованным ключом.** Один и тот же
клиент вводит одни и те же реквизиты в 15 документах; нормализация названия (юрформа,
кавычки, регистр, пунктуация) позволяет узнать организацию при любом написании.
Файл содержит ФИО реальных людей, поэтому в git не попадает и вынесен в переменную окружения.

**ADR-4. Журнал — каталог на каждую генерацию, включая неудачные.** Отвечает на вопрос
«сколько документов выпущено и чем заполняли», по образцу журнала прогонов сервиса проверки.
Запись под `try/except`: журнал не имеет права сорвать выдачу документа.

**ADR-5. Схема формы живёт в коде генератора, не в отдельном JSON.** Поля и шаблон меняются
вместе; хранить их рядом проще, чем синхронизировать два файла. Реестр и граф — единственные
внешние точки регистрации.
