## 1. Что это

`mos_generated` — dev-сервис, который **СОЗДАЁТ** документы `.docx`, заполняя docxtpl-шаблоны
значениями. Это **обратная сторона** чек-сервиса `mos_analiz_refactor` (тот ПРОВЕРЯЕТ документы —
см. его `ДОВОДКА_ПРАВИЛ_состояние.md`). Типы документов те же (проект по производительности труда:
приказы, положения, акты, протоколы, чек-листы). Замысел: сгенерировать документ → он проходит
проверку чек-сервиса на «Принято».

Заказчик: Мостратегия. Методцентр в документах — РЦК «Агентство стратегического развития».

## 3. Архитектура (репо)

```
mos_generated/
  generators/<тип>.py   # модуль на тип: DOC_TYPE, TITLE, TEMPLATE, SCHEMA(поля), generate(values)->DocxTemplate
  templates/<тип>.docx  # docxtpl-шаблон (чистый скелет с {{метками}})
  registry.py           # GENERATORS = {doc_type: класс} — единая точка регистрации
  graph.json            # узлы графа: {doc_type, title, position, code}; edges пусты (наследования нет)
  engine.py             # get_graph / get_schema / generate / сессии
  api.py                # FastAPI: /api/graph, /api/types/<t>/schema, /api/types/<t>/generate  (⚠ см. §7)
  static/index.html     # фронт генерации (одностраничный, ванильный JS)  (⚠ см. §7)
  _etalons/ _out/ _render/  # рабочие каталоги (эталоны, тест-выходы, рендеры) — в .gitignore/не коммитятся
  ТЗ_доработка.md       # ТЗ волн (скоуп/этапность)
```

**Контракт генератора** (скил §1.1): класс с `DOC_TYPE`, `TITLE`, `TEMPLATE`(путь), `SCHEMA`
(список `{key,label,type,required,source:"own",hint,[default]}`), `generate(values)`:
дефолты → мёрж значений → проверка required → `DocxTemplate(TEMPLATE).render(ctx)`.
Регистрация: импорт + строка в `registry.py` GENERATORS + узел в `graph.json`.

4. **Чистый скелет:** убрать ВСЁ привязанное к предприятию (данные + логотип, ВКЛЮЧАЯ скрытое —

## 6.1. Фиксы UI/UX (2026-08-20) и объединение с аудитом (2026-08-24)

### Четыре фикса по фидбэку владельца и коллеги (20.08)

**1. Документ не скачивался, но писал «скачан ✓».** Причина — клиентский механизм: ответ собирался в `blob`,
подставлялся во временный `<a download>` и сразу отзывался `revokeObjectURL`; браузер молча ничего не сохранял.
Заменено на **нативное скачивание**: `GET /api/types/{doc_type}/download?<все значения>&session_id=web`
отдаёт файл с `Content-Disposition: attachment`, фронт просто подставляет этот URL в **скрытый iframe**.
Никаких blob/anchor/revoke. Отдельно выяснено: если Chrome накопил зависшую очередь загрузок (бейдж с числом
при пустом `chrome://downloads`), он не сохраняет НИЧЕГО — лечится только `Cmd+Q`. Это сторона браузера, не сервиса.

**2. Ложное «скачан ✓» при незаполненных обязательных полях.** Теперь до скачивания собираются пустые
обязательные поля и выводится `«Заполните обязательные поля: <названия через запятую>»`, файл не запрашивается.
Валидация **data-driven по схеме конкретного типа** (у каждого типа свой набор), не хардкод.

**3. Автозаполнение по ООО.** Стор `_org_store.json`: ключ — нормализованное название организации
(`engine.normalize_org` снимает юрформу, кавычки, пунктуацию, регистр), значение — словарь `поле → список
ранее введённых значений` (свежие первыми, до 10). Пишется в конце `generate()`. Эндпоинты `GET /api/orgs`
(список известных ООО) и `GET /api/org/suggest?org=…` (значения по этому ООО). Фронт: `datalist` у каждого поля,
на `change`/`blur` поля `org_full` тянет подсказки, заполняет ПУСТЫЕ поля первым значением, остальные варианты
кладёт в выпадающий список. Проверено: ввод `эйай технологии` (нижний регистр, без юрформы) подтянул все 12 полей.
**Ограничение:** якорь — поле `org_full`; оно есть у 13 из 15 типов, у `polozhenie_ppu` и `polozhenie_comp_ppu`
полей организации нет вовсе, там автозаполнение неприменимо by design.

**4. Фикс шаблонов по замечаниям Саши.** Убрана серая подсветка пунктов (`<w:highlight w:val="lightGray"/>`)
и серая заливка (`<w:shd w:fill="F2F2F2">`) — были в 4 шаблонах из 15: `cheklist_eu`, `polozhenie_po`,
`prikaz_otvetstvennyh`, `prikaz_formirovanie_po`. В `prikaz_formirovanie_po` должность подписанта растягивалась
по всей ширине — `<w:jc w:val="both"/>` → `left`. Бэкапы: `/tmp/tpl_*.bak.docx`. Файлы «было/стало» для сверки

## 6.2. Журнал генерации — трейсы (2026-08-26)

**Зачем.** Руководство запросило факт: сколько документов выпущено за период. Ответить было нечем —
сервис отдавал файл в браузер и ничего не сохранял, логи uvicorn живут только до перезапуска.
В отчёте руководству строка «создано документов» осталась пустой. Проверка такой проблемы не имела:
там каждый прогон создаёт каталог-сессию, поэтому цифры нашлись сразу.

**Как сделано.** По образцу сессий аудита (`mos_analiz_refactor/src/audit/engine.py`) на каждый вызов
генерации пишется каталог:

```
logs_generated/<doc_type>/session_<ГГГГММДД_ЧЧММСС_мс>/
    meta.json      время, тип, session_id, IP клиента, статус ok|error, имя и размер файла, текст ошибки
    values.json    значения, которыми заполнялся документ (после наследования из сессии)
    <doc_type>.docx  копия выданного файла
```

Точка записи одна — `engine.generate()`; она обслуживает оба входа (`POST /api/types/{t}/generate`
и `GET /api/types/{t}/download`), поэтому трейс пишется независимо от того, как запросили документ.
IP клиента прокидывается из `api.py`.

**Два решения:**
- **копию документа храним** — иначе журнал отвечает «сколько», но не «что именно выпустили»
  (документ ~75 КБ, на диске 37 ГБ);
- **неудачные попытки тоже пишем** (`status: "error"`, без файла) — видно, сколько раз документ
  не удалось получить и почему.

**Отказ журнала не роняет генерацию.** `_write_trace` целиком под `try/except`: если каталог
недоступен, документ всё равно выдаётся, а сбой уходит в лог сервиса. Проверено: при `chmod 500`
на каталоге журнала генерация вернула HTTP 200 и файл 46 338 байт, в логе — строка `[trace] не удалось...`.

**Проверено (26.08):** успешная генерация через POST и через GET — трейс со `status: ok`, размер
совпадает с отданным, `.docx` открывается (16 элементов в архиве, `word/document.xml` на месте);
пустые обязательные — API по-прежнему 400, трейс со `status: error` и текстом ошибки; сквозной путь
через объединённый UI (`mosaudit.ru.tuna.am` → прокси `/gen`) — трейс записан с внешним IP.
Тестовые трейсы после проверки удалены, учёт начат с чистого листа.

**Счёт для отчётности:**
```
find ~/projects/mos_generated/logs_generated -maxdepth 2 -type d -name "session_*" | wc -l   # всего
grep -l '"status": "ok"'    logs_generated/*/session_*/meta.json | wc -l                      # успешных
grep -l '"status": "error"' logs_generated/*/session_*/meta.json | wc -l                      # неудачных
```

**Чего журнал не покрывает.** Кто именно сгенерировал документ — у сервиса нет авторизации, все
запросы идут с `session_id="web"`, пишем только IP. И правил ли человек документ после скачивания —
это происходит вне сервиса; долю ручной доработки можно узнать только опросом.

  снимать `r.font.highlight_color=None`. **nbsp `\xa0`** в датах → `re.sub`.

  фикс. минимумом строк проще N фикс. строк с метками `specN_*`, не цикл.
- **Форма-бланк vs заполненные метки — по правилу чек-сервиса:** где правило допускает «поле для…» —
  оставлять ПУСТЫМ (cheklist оценки/итог); где требует «заполнено реальными» — метки (formirovanie_po).
- **Устаревший рендер** перед критиком → `rm pdf` перед soffice. **base64 со стенда — только `-i`.**
  **pdftoppm при >9 стр. паддит ведущим нулём** (`et-01.png`, не `et-1.png`). **Кириллица/№ в путях** →
  python `os.listdir`+`unicodedata.normalize("NFC")`, не splitext/glob. **Мак-скрипты в `$TMPDIR`.**
- **`dev` = SSH ControlMaster.** `pkill/pgrep -f <шаблон>`, где шаблон встречается в строке самой
  ssh-команды, **убивает свою сессию** → stale master-сокет → все `dev` = 255. Фикс: bracket-трюк
  `[m]ain.py`/`[u]vicorn`; на 255 — сначала `dev -K`, потом ретрай. Файлы стенда опрашивать через `dev`,
  НЕ локальным `until` (иначе вейтер висит вечно). VPN мигает → `dev -K; sleep 2` + ретрай.
